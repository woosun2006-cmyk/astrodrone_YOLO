### 판정 기준을 중심거리에서 가장자리간격으로 바꾼 이유

처음에는 "중심 간 거리 / 박스 크기" 로 판정했다(임계 0.8). 그런데 실측 비율이
**0.85 ~ 0.89** 로 나와 임계선에 아슬아슬하게 걸렸다. 값을 조금 올리면 물리적으로
다른 두 타겟(고도 4 m, 1 m 간격 → 비율 1.16)까지 삼킬 위험이 있었다.

가장자리 간격은 **부호가 갈린다.**

```
한 물체의 조각   : 간격 −7, −3, −6 px   (붙어 있거나 겹침)
서로 다른 두 타겟 : 간격 +7 px           (떨어짐)
```

물리적으로도 자명하다 — 한 물체를 쪼갠 박스들은 서로 맞닿아 있고, 다른 물체는
사이가 벌어져 있다. 이 기준이면 임계값이 판정선 한가운데에 놓인다.

## 디버깅

`gazeboSim/gazebo_yolo_target.py` 에 NMS 뒤에 붙는 **근접 병합** 단계를 넣었다.
NMS 는 많이 겹치는 중복을 지우고, 이건 겹침이 적어 NMS 를 통과했지만 실은 한
물체에 붙어 있는 조각들을 묶는다.

```python
def _touching(a, b, gap_frac):
    gap_x = abs(a["cx"] - b["cx"]) - (a["w"] + b["w"]) / 2.0
    gap_y = abs(a["cy"] - b["cy"]) - (a["h"] + b["h"]) / 2.0
    margin = gap_frac * max(a["w"], a["h"], b["w"], b["h"])
    return gap_x <= margin and gap_y <= margin
```

`MERGE_GAP_FRAC = 0.1`. 실측 −7 px 와 +7 px 사이를 가르며, 4 m 사례의 여유폭
4.4 px 보다 작으므로 서로 다른 타겟은 병합되지 않는다.

세 가지를 함께 처리했다.

1. **사슬 병합** — 군집에 들어온 박스가 대표의 경계를 합집합으로 넓힌다. 타겟이
   세 조각 이상으로 쪼개져도 이어 붙는다.
2. **대표 위치를 합집합 중심으로** — 조각 하나의 중심을 쓰면 최고신뢰가 좌/우
   조각을 오갈 때마다 `x_px` 가 튄다(실측 −28 ↔ +26). 합집합 중심은 그 진동을
   없앤다.
3. **진단 노출** — 로그에 `박스=2→1`, `/target` 에 `boxes_raw` / `objects` 추가.

`--merge-frac` 로 조정 가능하고 음수면 병합하지 않는다.

## 남은 문제

1. **`SIM_FX` 는 여전히 수동이다.** 이번 성공도 `SIM_FX=205.47` 를 준 실행이다.
   기본값은 `pixel_focal_length_px: 530` 이고, 그대로 두면 수평 유도가
   2.58배 과소평가되어 거의 수직으로 내려온다. 실기 IMX219 의 초점거리는 아직
   측정된 적이 없다 — **실비행에서 같은 증상이 재현될 수 있다.**
2. **실기 TensorRT 경로에는 근접 병합이 없다.** `YOLO_MODEL/cpp/trt_engine.cpp`
   는 NMS 만 한다. 근접에서 타겟이 쪼개지는 것은 모델의 성질이므로 실기에서도
   같은 일이 일어날 가능성이 높다. C++ 쪽에도 같은 병합을 넣어야 한다.
   `WHITE_BASKET_SETUP.md` 의 재현 조건(고도 4 m 고정)은 이 구간을 밟지 않아
   드러나지 않았다.
3. **하향 카메라에 기체 자기 구조물이 찍힌다.** 이번 근접 케이스의 두 박스는
   모두 타겟이었지만, 드론 타겟 실험에서는 모델이 모서리 구조물에 0.10~0.87 로
   반응했다. 근접 병합은 이걸 걸러주지 않는다(멀리 떨어져 있으므로 별개 물체로
   남고, 오히려 다중검출 판정을 유발한다). ROI 크롭이 필요하다.
4. **`stop_hover_sec` 이후 착륙은 GUIDED LAND 이고**, 타겟 위 0.21 m 까지
   내려갔다. 실제 임무에서 이 마지막 구간을 어떻게 할지는 별도 결정이 필요하다.
